## 3. Ordering rules the project must obey later (runbook)

Every guide agrees on the skeleton; where they differ, the tool author's own doc wins. All tools run through MO2's VFS (TOOLCHAIN.md already mandates this for LOOT and xEdit), into dedicated output folders outside the instance, then installed as ordinary mods at the priorities below.

**A. Pre-generation (once, and again after any of the triggers in C):**
1. Finalize the mod list. Install every mod that touches exteriors, trees, grass, landscape textures or meshes, plus its patches. DynDOLOD: "Finalize the load order. Install mods and their requirements. Sort and resolve conflicts."
2. Clean. Re-clean the 1.7.104 `Update.esm`, `Dawnguard.esm` (plus its manual `RiftenRatwayZone` XEZN edit per TPF/Lexy), `HearthFires.esm`, `Dragonborn.esm`, `ccBGSSSE001-Fish.esm`, `ccBGSSSE025-AdvDSGS.esm`, `ccQDRSSE001-SurvivalMode.esl`, and any mod plugin LOOT flags. Put the cleaned files in a `Cleaned Vanilla Masters` MO2 mod directly above the DLC/CC rows and restore Steam's originals to `Data` (STEP/TPF/Lexy). Never touch `Skyrim.esm`.
3. Sort with LootCLI, then `install_mod.py --sort` re-enable, then `verify_order.py`. Lexy also runs xEdit "Sort Masters" on all plugins.
4. Synthesis first only if a patcher group is configured (CS wiki puts Synthesis before BodySlide; Synthesis's own docs only require group order = load order and Bashed Patch before Synthesis). Keep `Synthesis.esp` enabled while rerunning.
5. BodySlide batch build via CLI (`BodySlide.exe --groupbuild "<groups>" --preset "CBBE Curvy" --targetdir "<BodySlide Output mod>" --trimorphs`) into a `BodySlide Output` mod set in BodySlide's own settings, never via MO2's create-files-in-mod (PGPatcher wiki). Enable it.
6. Pandora with `-o "<Pandora Output mod>"` (`--auto_run --auto_close` for headless), output mod enabled; rerun after every animation or skeleton mod.
7. PGPatcher (when PBR/parallax textures are present): MO2 conflict resolution, "Lock order to MO2", output to an empty, disabled `PGPatcher Output` mod, then enable it above everything except the LOD outputs; `PGPatcher.esp`/`PG_X.esp` load last except DynDOLOD/Occlusion. Nothing with meshes may ever be placed after it.
8. Grass cache (only once a grass mod and NGIO exist): precache into a `Grass Cache` mod; the cache is a prerequisite for grass LOD billboards.

**B. LOD chain, in this order, each installed and enabled before the next runs:**
9. xLODGen: install `SSE Terrain Tamriel Extend` temporarily, Terrain LOD only, all worldspaces, BC7 Quick, at 4K double STEP's sizes; disable the Terrain Tamriel plugin afterwards. Output mod `xLODGen Output`.
10. ACMOS Road Generator, "Paths Only", onto the xLODGen output (reinstall ACMOS with its LOD option first, #81).
11. TexGen (`-sse`), 4K preset (TPF: 512 stitched/rendered, 5.5 units per pixel), HD tree billboards, grass billboards only if a grass cache exists; with CS set `TreeNormalMaps=0` / `TreeLODComplexAtlas=0` (CS GitHub FAQ). Remove old TexGen output first. Output mod `TexGen Output` above everything, including PGPatcher.
12. DynDOLOD (`-sse`), all worldspaces, High preset, Candles + FXGlow, Ultra trees, Occlusion on the first run only (quality 3), Terrain underside, Upgrade NearGrid large refs to FarGrid; at 4K max tile LOD 2048 / full 512 (TPF). Output mod `DynDOLOD Output` last. `DynDOLOD.esm` after the last other ESM; `DynDOLOD.esp` then `Occlusion.esp` last. Sort with LOOT once, then no more LOOT re-sorts until the outputs are disabled again (Lexy).
13. Launch, new game or interior clean save, exit to an exterior, wait for "DynDOLOD successfully initialized"; run `launch_triage.py`.

**C. What a later mod addition forces (DynDOLOD "When to regenerate", STEP, Nordic Souls):**
- Any mod: LOOT sort, `verify_order.py`, Synthesis rerun if a group exists.
- Outfit/body mod: BodySlide rebuild, then PGPatcher rerun ("if you add mods that add new meshes or change any meshes").
- Animation/skeleton mod: Pandora rerun.
- Texture-only mod (landscape or object): xLODGen if `textures\landscape\` changed; TexGen, then DynDOLOD "Rebuild Atlas" (or full rerun); PGPatcher rerun if it carries parallax/CM/PBR maps.
- Any plugin that adds, moves or removes exterior objects, trees, grass, or landscape height: full TexGen + DynDOLOD from scratch; Occlusion only if TVDT-relevant geography changed.
- Grass mod or grass INI density change: grass cache, TexGen, DynDOLOD.
- Removing a plugin that is a master of `DynDOLOD.esp`/`Occlusion.esp`: regenerate from scratch.
- Before regenerating in an existing playthrough: DynDOLOD MCM "DynDOLOD is active" off, enter an interior, save, remove old outputs, load and save again, then regenerate (TPF "How To Update"; DynDOLOD "Clean Save").

## 4. Things the guides say NOT to do that the project currently does

1. **Cleaning masters in `Data` instead of an MO2 mod.** STEP/TPF/Lexy all keep vanilla files untouched and put cleaned copies in a mod; the project's in-place clean was silently undone by the 1.7.104 update, and the ledger still describes the masters as cleaned (`records/baseline.json`).
2. **Global (non-profile) INIs and saves.** Every guide enables profile-specific INIs; the project's smoke profile has to rewrite `LocalSettings` to isolate itself.
3. **ENB-era particle lights on CS.** CS FAQ: "Particle lights or ENB lights ... Limited support was reintroduced in 1.8. However, it is recommended to instead use Light Placer"; Vanilla Setup: "CS Particle Patch fixes lighting on countless vanilla meshes ... make sure CS Particle Patch overwrites [ENB Particle Patch]".
