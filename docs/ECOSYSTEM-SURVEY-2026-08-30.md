## 3. Process observations

- **Generation order is standardised.** Nordic Souls documents "BodySlide > Synthesis > ParallaxGen > LOD" and forbids LOOT: "you should not run LOOT to sort mods" ([MODIFICATIONGUIDE](https://github.com/Geborgen/nordic-souls/blob/main/MODIFICATIONGUIDE.md)). Lexy's pre-install page lists the same toolchain with versions: xEdit 4.1.5f, DynDOLOD 3 Alpha-205, xLODGen, Synthesis 0.36.5, LOOT 0.29.1, CAO 5.3.15, Wrye Bash, zEdit/zMerge, BethINI Pie ([link](https://lexyslotd.com/guide/preinstallation-instructions/)). STEP runs TexGen then DynDOLOD into dedicated output mods and adds Grass Cache Helper NG and ACMOS Road Generator ([STEP 2.3](https://stepmodifications.org/wiki/SkyrimSE:2.3)). This build does LOD last by design (BASELINE decision order) but has no documented BodySlide -> Synthesis -> PGPatcher -> xLODGen -> TexGen -> DynDOLOD -> Occlusion sequence yet.
- **Synthesis is the patch generator, not hand-built ESPs.** 14/19 exports ship a Synthesis output; LoreRim ships "Requiem - Auto NPC Patcher" and an xEdit64 output; GTS ships `GTS Patches - Old Synthesis.esp`; Anvil, CSVO and Apostasy document Synthesis. Which patchers are configured is not published in the exports (the `.esp` only), so no ranking of individual patchers is possible from this evidence; NS notes one output ("Synthesis - IED Meshes.esp") is optional. The Synthesis Collective hosts the common ones (Speed and Reach Fixes, SynthEBD, Enemy Releveler, NPC Appearance Copier) ([org](https://github.com/Synthesis-Collective)). The project's hand-built ESP-FE overrides are the older Wrye/xEdit style.
- **PGPatcher is mandatory in the CS/PBR lineage.** CSVO: "ParallaxGen (for PBR mesh conflict resolution)"; NS has "NS - PGPatcher Output - ENB"; 8/19 ship an output. BASELINE already gates Vanaheimr on "CS/PGPatcher path is ready"; the ecosystem confirms PGPatcher is the tool, and AutoBlend (SLOT_CANDIDATES 188398) is a PGPatcher addon, not a replacement.
- **Stock Game + Root Builder is how lists survive Steam.** Nordic Souls, LoreRim, NGVO, Nolvus, GTS-WJ all copy the game into the list folder and pin it; Wabbajack "auto-downgrades the stock game folder" (reported in the 1.6.1170 Missing Files discussion, [Nexus 189256](https://www.nexusmods.com/skyrimspecialedition/mods/189256)). This project runs the live Steam install instead.
- **MCM presets ship as MCM Recorder (NS, Anvil, Tempus, NGVO) or list-owned "MCM and INI Settings" mods (LoreRim).** This build has no preset layer yet.
- **Load order:** the big lists hand-sort (NS, TPF forbid LOOT); STEP and Lexy use LOOT with custom rules. `install_mod.py --sort` (LOOT) matches the guide practice, not the list practice.
- **Save-system layer:** Skyrim Save System Overhaul 3 appears in GTS and Lexy; neither it nor Clean Save Auto-reloader (SLOT_CANDIDATES) is installed.

## 4. 1.7.x readiness

Timeline: 1.7.99 released 2026-08-20 with SKSE 2.3.0; 1.7.104 on 2026-08-27 with SKSE 2.3.1 ([skse.silverlock.org](https://skse.silverlock.org/), [Steam news](https://store.steampowered.com/news/app/489830/view/681885122980479679)). Address Library v12 shipped the same day with the note that "other changes made to game code require plugins to update CommonLib and recompile" ([Nexus 32444 posts](https://www.nexusmods.com/skyrimspecialedition/mods/32444?tab=posts), reported).

- **No surveyed list has migrated its runtime to 1.7.x.** Every README that names a version says 1.6.1170 (Anvil, Apostasy, CSVO, NGVO, Tuxborn, Wildlander, Nordic Souls, Lexy, STEP, GTS-WJ). Nordic Souls 3.2.0/3.2.1 (LOL 2026-08-28) is the only post-update release found and says both "Recompiled the list against SSE version 1.7.99" and "The actual list is still running on 1.6.1170. You just need to update Skyrim" (documented): the Steam install is 1.7.99, the Stock Game copy stays 1.6.1170.
- **LoreRim's site says "The specific version used is 1.7.99"** while its GitHub README says 1.5.97 with 1.6.1170 CC content and Stock Game. Unresolved; the LOL export predates the update (2026-06-02). Treat as [unverified] until a post-August LoreRim release is inspected.
- **STEP 2.3 states the plan explicitly:** stay on 1.6.1170 via downgrade patcher; "When all such DLL mods in this guide are updated for game v1.7.99, then the downgrade patcher becomes obsolete, and Skyrim.exe and all SKSE-dependent DLL mods should be updated" (documented). No STEP or Lexy 1.7.x release exists yet.
- **How they handle the DLL gate:** they don't; they avoid it by pinning the runtime. Tools the community reports for that: Best of Both Worlds patcher 1.7.104 -> 1.6.1170/1.5.97 ([169962](https://www.nexusmods.com/skyrimspecialedition/mods/169962)), Skyrim Downgrade Tool ([188916](https://www.nexusmods.com/skyrimspecialedition/mods/188916)), 1.6.1170 Missing Files for the two files removed after 1.7.99 ([189256](https://www.nexusmods.com/skyrimspecialedition/mods/189256)), Creation Kit downgrade patcher ([190110](https://www.nexusmods.com/skyrimspecialedition/mods/190110)).
- **Community Shaders:** 1.8.4 is reported incompatible with 1.7.99/1.7.104; 1.7.99 support on the dev branch as of 2026-08-28 with no release ETA ([Nexus 86492 posts](https://www.nexusmods.com/skyrimspecialedition/mods/86492?tab=posts), reported). That means GTS, Anvil, CSVO, Septimus and Tuxborn (CS lists) cannot run on 1.7.104 as shipped; this build's self-built CS AIO is ahead of every list.
- Consequence: the timestamp gate in `PluginManager.cpp` (BASELINE) and the rebuild queue (#87) are work no surveyed list has done. The ecosystem's answer is "wait on 1.6.1170"; expect no list-level precedent for 1.7.x-only DLL sets before the next STEP/Lexy cycle.
