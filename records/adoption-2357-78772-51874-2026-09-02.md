## 1. Enhanced Blood Textures - Lite (2357)

### 1.1 File choice

`records/blood-visuals-audit-2026-08-30.md` ranked decision #2 as "EBT Lite 1.1
plus the existing `Disable Screen Blood`", and #3 as "do not choose full EBT
SPID for this slot". **The archive audit does not contradict that record**, so
Lite was installed as directed.

The page has two `MAIN` files - 68999 (Lite 1.1) and 249235 (full 4.0). `pick_file`
takes the newest MAIN, which is the full version, so the install was pinned with
`--file 68999`. Author's own file note on 68999: *"Plugin and textures only.
This should be set at the top of your load order to avoid conflicts with mods
that edit body data. Do not use with main download!"*

Archive contents (7z listing): `data\dD - Enhanced Blood Main LITE.esp`,
15 `.dds`, `data\fomod\info.xml`, `Enhanced Blood Textures.txt`. Installed
through `records/fomod-plans/2357-ebt-lite.json`, which maps only the plugin
and `data/textures`, so the fomod metadata and the readme are not staged as
game data.

### 1.2 Optimised Scripts for EBT (76767) - **not applicable, not installed**

76767 ships five replacement `.pex` files (`zbloodEBTmenu`, `zbloodnpc`,
`zbloodnpcbleed`, `zbloodnpccreatures`, `zbloodnpcquestupdatescript` - verified
from both MAIN archives 322507 / 322508). **EBT Lite ships no scripts at all**
(15 DDS + 1 ESP, listing above), so there is nothing for it to optimise. It
applies only to the full/SPID build, which is the variant the blood audit told
us not to choose. Not installed.

### 1.3 Spider Blood Fix (114039) - not applicable

Flagged by `ecosystem.py` as a 2024 companion. It corrects blood colour on
mod-added spiders. EBT Lite's 15 `BodyPartData` overrides are DefaultBodyPartData,
SabreCat, Skeever, Cow, Dog, Giant, Falmer, Hare, Goat, Deer, Bear, Horker,
Hagraven, Chicken, WerewolfBeast - **no spider record** - so the system it
patches does not exist in the Lite build. Not installed.

### 1.4 Screen-effect policy - held, with the arithmetic

The blood audit's "Non-negotiable screen-effect configuration" requires
`Disable Screen Blood` to keep winning. Record-level facts
(`skyrim-record-cli record-fields-by-type`):

- `Disable Screen Blood.esp` sets 15 `fBloodSplatter*` GMSTs to **0**.
- EBT Lite sets 9 of those same 15 to non-zero (e.g. `fBloodSplatterDuration`
  6, `fBloodSplatterMaxSize` 0.35, `fBloodSplatterMinOpacity` 0.8), plus
  `iBloodSplatterMaxCount`.
- Post-sort winner check (`records/active-record-conflicts.json`): EBT Lite
  **loses all 8 shared FormKey GMSTs to `Disable Screen Blood.esp`**, and loses
  the ninth (`fBloodSplatterCountBase`, a new record in both plugins, so
  resolved by EditorID) to it as well because Disable Screen Blood is at
  position 122 and EBT Lite at 33.

The one GMST `Disable Screen Blood` does not cover is `iBloodSplatterMaxCount`.
EBT **lowers** it, from vanilla `25` (read from `Skyrim.esm`) to `10`. Screen
blood is off today at 25, so a ceiling of 10 cannot re-enable it. The optional
`dD-No Screen Blood.esp` (file 64692) is a strict superset of
`Disable Screen Blood.esp` - same 15 zeros plus `iBloodSplatterMaxCount = 0` -
so it would add one redundant full ESP for a value that is already inert.
**Not installed.**

`No More Blur on Hit` (`NoRadialBlurOnHit.esp`, one IMAD `GetHit` record) does
not intersect EBT Lite at all. Sanguine Symphony is not installed, so the
"never mix with Sanguine" constraint is satisfied.

### 1.5 The one real regression

Pre-install and post-sort scans agree: EBT Lite's total conflict surface across
the 238-plugin order is **10 FormKeys**. Eight are the screen-blood GMSTs above.
The other two are Impact records:

| record | vanilla | Audio Overhaul / ISC | EBT Lite | post-sort winner |
|---|---|---|---|---|
| `WPNArrowVsFleshImpact` (0193B2) | Sound2 `0EA9F8`, TXST `01F827` | Sound2 **null**, TXST vanilla | Sound2 vanilla, TXST **`00DA05` (EBT's DecalBloodArrowHit)** | `Audio Overhaul Skyrim.esp` |
| `WPNAxeLargeVsFleshDraugrImpact` (0F0EB1) | Sound1 `0F600F` | AOS + ISC each set their own Sound1 | **identical to vanilla (ITM)** | `Immersive Sounds - Compendium.esp` |

The second is an ITM in EBT, so losing it costs nothing and correctly preserves
ISC's draugr-axe sound. The first is a genuine loss: arrow hits on flesh use
EBT's blade decal (`DecalBloodBladeHit`, which EBT *does* win) instead of its
dedicated arrow decal. **This is the correct trade** - the alternative ordering
would restore a vanilla sound AOS deliberately removed and revert ISC's draugr
sound, two audio regressions for one decal. Tracked as an issue for a
one-record forward patch; not fixed in this batch.

for the user's eyes rather than treated as a rejection - the mod was approved,
and a mip-resharpen recipe is available if the look disappoints in game.

of its bytes: the install is the unmodified Nexus archive, and no overlay was

`docs/TEXTURE_POLICY.md` allows source plus at most one conventional step, hard
capped at 4096. The 4K package would put 15 further sets **two** steps above
their 1024 vanilla sources, so it is rejected. The 2K package puts most sets at
2048, exactly one step. **Three sets in the 2K package are still 4096**
(Boethiah, Peryite, Clavicus Vile): Clavicus Vile's vanilla source is 2048 so
that is one step; Peryite has no vanilla statue texture at all and Boethiah's
is 1024, so those two sit one step above the closest large-statue analogue
(the 2048 tier: `mehrunesstatue01`, `clavicusvileshrine`, `statuemara01`,
`statuetalos01`, `statuefalmer`) and two above their nearest same-prince
texture. Both readings stay under the hard cap. Recorded as an issue for a
possible `Ensrick - Daedric Shrines Texture Cap` overlay rather than modified
silently; the author's terms ("You are free to use my models and textures for
your mod, as long as it's hosted on Nexus") permit a local-only downscale.

**Map markers: the main ESP was kept, not the "No map markers" ESP (536023).**
The two plugins carry an identical record set; a field-level diff shows they
differ in exactly 7 `MapMarker` refs plus one incidental placement. Every one
of the main ESP's markers has `Flags = "0"` - neither `Visible` nor
`CanTravelTo` - i.e. ordinary undiscovered-location behaviour: you find them by
exploring, they are not handed to you. That is in keeping with the build, and
`A Clear Map of Skyrim` is a map presentation overhaul, not a marker manager,
so there is no interaction.

## 3. Remiel - Dwemer Specialist (51874)

Maplespice, 11,056 endorsements. The build already runs the same author's
`Varinia` (148853, `VLIOVarinia.esp`), so the custom-framework follower pattern

### 3.1 Runtime and framework requirements

- **No DLL, no SKSE plugin, no script extender dependency.** The 7z contains
  only `.esp`, `.bsa`, `.nif`, `.dds` and the FOMOD - verified from the full
  file listing. There is nothing for the 1.7.104 runtime to reject.
- Author's own requirements line: *"None except the DLCs."*
- **AFT is an outright incompatibility** and is not installed anywhere in the
  order. Satisfied.
- **NFF is a soft incompatibility and NFF *is* installed** (`nwsFollowerFramework.esp`).

  NFF's exclusion is an in-game MCM action - its mod folder holds only class
  presets and translations, no INI or JSON blacklist - so this is an operational
  rule for the user, not a file we can pre-set:
  **do not import Remiel into NFF.**
- Save state: *"If you are installing Remi for the first time at 1.6.0+, then it
  is fine on an ongoing save."* First-time install, so the existing test save is
